## 要件1: レビュー報酬システム（Amazonギフト券配布機能）

### 背景・目的
レビュー数を爆発的に増やすため、Amazonギフト券による報酬システムを構築する。

### 基本方針
- **対象期間**: 一定期間（キャンペーン形式）
- **対象レビュー**: 期間中の全レビュー
- **報酬**: Amazonギフト券（例: 300円）
- **品質管理**: LLMによる自動精査で一定基準以上のレビューのみ報酬付与

---

### 機能概要

#### 1. Amazonギフト券管理機能

**方式**:
- 事前に購入したAmazonギフト券のURLを手動で登録
- 1つずつ消費していく方式

**データ構造**:
```
gift_codes テーブル
- id: ギフトコードID
- url: AmazonギフトURL（暗号化保存）
- label: ラベル（例: "300円", "500円"）
- is_used: 使用済みフラグ
- used_at: 使用日時
- used_by_user_id: 使用者
- created_at: 登録日時
```

**必要な機能**:
- [ ] 管理画面でギフト券URL登録
- [ ] ラベル設定（金額識別用）
- [ ] 在庫状況の確認
- [ ] 在庫アラート機能（残数が少なくなったら通知）

---

#### 2. レビュー品質管理機能（LLM精査）

**目的**:
一定基準以上のレビューのみに報酬を付与し、品質を担保する。

**フロー**:
1. ユーザーがレビューを投稿
2. LLMが自動で内容を精査
3. 基準以上 → 承認 → 報酬付与
4. 基準以下 → 改善指示 → 再提出を促す

**精査項目（検討中）**:
- [ ] 文字数の適切性
- [ ] 具体性・詳細さ
- [ ] 5軸評価との整合性
- [ ] 誹謗中傷・不適切表現のチェック
- [ ] その他（次回詰める）

**データ構造**:
```
review_quality_checks テーブル
- id
- review_id: レビューID
- llm_model: 使用したLLMモデル名
- score: 品質スコア
- status: ステータス（pending/approved/rejected）
- feedback: 改善指示内容
- checked_at: 精査日時
```

**未確定事項**:
- [ ] 使用するLLMモデル（GPT-4, Claude, Gemini など）
- [ ] 具体的な評価基準
- [ ] 改善指示の生成方法（自動 or 手動）
- [ ] 再提出回数の上限
- [ ] 最終判定（自動承認 or 人間による確認）

---

#### 3. 報酬受領機能

**UI仕様**:
- マイページに受領可能なAmazonギフト券の一覧を表示
- 初期状態: URLは非表示
- 「表示」ボタンをクリック → URLまたは「受領済み」を表示
- ボタンクリック時点で受領とみなす

**データ構造**:
```
rewards テーブル
- id
- user_id: ユーザーID
- review_id: レビューID
- gift_code_id: ギフトコードID
- status: ステータス（pending/claimed）
- claimed_at: 受領日時
- created_at: 報酬付与日時
```

**画面イメージ**:
```
マイページ > 報酬一覧

┌─────────────────────────────────────┐
│ Amazonギフト券                       │
├─────────────────────────────────────┤
│ 300円 | 2025-12-01 | [表示]         │
│ 300円 | 2025-12-05 | [表示]         │
│ 300円 | 2025-12-10 | 受領済み       │
└─────────────────────────────────────┘
```

**未確定事項**:
- [ ] 「表示」ボタンを押した後の挙動（一度押したら二度と表示できない？）
- [ ] 受領済み時にURLも表示する？ それとも「受領済み」のみ？
- [ ] ギフト券の有効期限表示の必要性

---

#### 4. 運用フロー（全体）

```
[ユーザー] レビュー投稿
    ↓
[システム] LLMで品質精査
    ↓
    ├─ 基準以下 → 改善指示 → 再提出
    └─ 基準以上 → 承認
         ↓
    [システム] Amazonギフト券を割り当て
         ↓
    [ユーザー] マイページで確認
         ↓
    [ユーザー] 「表示」ボタンクリック
         ↓
    [システム] URL表示 & 受領記録
```

---

### セキュリティ要件

**検討事項**:

- [ ] 1ユーザーあたりの報酬上限設定
- [ ] 不正レビュー検知機能（同じ内容の使い回し等）
- [ ] ギフト券URLの不正アクセス防止

---

### 未確定事項（次回詰める）

   - 開始・終了の管理方法

   - 評価項目の詳細
   - スコアリング方法
   - 改善指示のテンプレート

3. **管理画面の要件**
   - ギフト券の一括登録機能（CSVインポート等）
   - レビュー承認・却下UI
   - 統計情報（配布数、受領率など）

4. **実装優先順位**

## 要件2: YouTube動画から店舗登録機能

### 背景・目的
店舗情報の登録を効率化し、運営者一人でもレビューを作成できるようにする。

### 基本方針
- YouTube動画のURLを入力
- サムネイルを自動取得して店舗画像として使用
- 店舗情報（ラーメンの種類、所在地など）は動画を見て手動入力
- その後、運営者がレビューを作成

---

### 機能概要

#### 1. YouTube動画情報取得機能

**入力**:
- YouTube動画のURL

**自動取得する情報**:
- サムネイル画像
- （検討中）動画タイトル
- （検討中）チャンネル名
- （検討中）投稿日

**技術要件**:
- YouTube Data API v3を使用
- API制限: 1日1万リクエスト

**未確定事項**:
- [ ] サムネイル以外に自動取得する情報
- [ ] 取得した情報の活用方法（店舗名候補、参考情報など）

---

#### 2. 店舗登録フォーム

**入力項目（手動）**:
- 店舗名
- 住所
- 最寄駅
- 路線
- カテゴリ（家系、二郎系など）
- タグ（朝ラー、健康志向など）
- その他店舗情報

**画面イメージ**:
```
┌─────────────────────────────────────┐
│ YouTube URL                         │
│ [https://youtube.com/watch?v=...]   │
│ [サムネイル取得] ボタン              │
├─────────────────────────────────────┤
│ サムネイル:                         │
│ [画像プレビュー]                     │
├─────────────────────────────────────┤
│ 店舗名: [___________]               │
│ 住所:   [___________]               │
│ 最寄駅: [___________]               │
│ ...                                 │
│ [登録] ボタン                        │
└─────────────────────────────────────┘
```

**未確定事項**:
- [ ] 必須項目の定義
- [ ] 店舗登録と同時にレビュー作成？ それとも別操作？
- [ ] YouTube情報（動画URL、タイトル等）を店舗情報に紐付けるか

---

#### 3. レビュー作成との連携

**運用フロー**:
1. 運営者がYouTube URLを入力
2. サムネイル自動取得
3. 動画を見ながら店舗情報を入力
4. 店舗登録
5. （同時 or 別途）レビューを作成

**未確定事項**:
- [ ] 店舗登録後のフロー（レビュー作成画面に遷移？）
- [ ] YouTube動画から得た情報をレビューに活用する方法

---

### データベース設計（検討中）

**追加カラム候補**:
```
restaurants テーブル
- youtube_url: YouTube動画URL（NULL可）
- youtube_title: 動画タイトル（参考情報）
- youtube_channel: チャンネル名（参考情報）
- source_type: 登録元（manual/youtube/other）
```
